# Stack

Every technology the bakery uses or plans to use: its pin, what it owns, why it won, and what came second; also what was rejected, when upgrades happen, and what is new to learn. The choices that shape the rest have their own ADRs, listed under Doors below. Toolchain mechanics are in [delivery.md](delivery.md), prices in [cost.md](cost.md).

Status: Draft for review in PR 1 · 2026-11-04

## Shape

The made-up bakery is two systems on the site's Cloudflare account and zone. Astro builds the storefront and staff console as static files, and an assets-only Worker, `bakery-web`, serves them, so a public page view runs no code. Everything on a server is Rust: one Worker, `bakery-api`, compiled to `wasm32-unknown-unknown`, which holds every Durable Object (DO) class, the Queue consumer and the cron handler. The domain lives in crates that know nothing about Cloudflare, so `cargo test` runs it natively. State is SQLite-backed DOs, one per aggregate. GitHub Actions builds, gates and deploys.

## Upgrade policy

Upgrades arrive as Dependabot PRs and pass the same pipeline as everything else. Versions and dates are as of 2026-11-04. The Dependabot configuration is in [delivery.md](delivery.md).

| What | Rule | Why |
|---|---|---|
| Pins and Dependabot | Every crate and package is pinned exactly; lockfiles are committed; CI passes `--locked`. Dependabot (cargo, npm, github-actions) opens one grouped weekly PR for minors and patches, and a major in its own PR | A build is the same everywhere, an upgrade is a visible diff, and a major gets a migration note |
| `worker`, `worker-build` | Exact pins that move together; read the changelog before every bump, because workers-rs is 0.x and a minor may break | Two breaking releases in a year ([site ADR 0014](https://github.com/IHaveASegway/website/blob/main/docs/adr/0014-typescript-on-workers.md)) |
| `wasm-bindgen` | Follows `worker`, never bumped by hand | The two must agree on the Wasm interface |
| Rust | Track stable within a month of each release | An old toolchain drifts from the crates' minimum versions |
| Stripe API version | Pinned in a header on every call; bumped in its own PR | An unpinned version changes under a running system |
| Astro, Wrangler, Node, pnpm, TypeScript, VROOM, gitleaks | The site's rules, taken from [its upgrade policy](https://github.com/IHaveASegway/website/blob/main/docs/stack.md#upgrade-policy): Astro majors wait for x.1; Wrangler `^4.152.0`; Node on the Active LTS line; pnpm 11.x; TypeScript 6.0.x; VROOM by copying the site's newer build; gitleaks bumped quarterly with its sha256 | Two repositories upgrade the same way |
| `compatibility_date` | Bumped quarterly, alone, per Worker, after reading the flag changes | A stale date is a missing feature, not an outage ([docs](https://developers.cloudflare.com/workers/configuration/compatibility-dates/)) |

## What you need to understand to run this

The storefront half is the site's stack. The new parts are Rust on Workers and the DO model, with one official page each; limits are as of 2026-11-04. All four matter for PR 2 and spike S1.

| # | Layer | New here | Read first |
|---|---|---|---|
| 1 | Rust on Workers | The target is `wasm32-unknown-unknown`: no threads, no filesystem, no Tokio. `worker-build` compiles the crate and writes the JavaScript shim. Async runs on the Workers event loop | [Rust on Workers](https://developers.cloudflare.com/workers/languages/rust/) |
| 2 | Durable Objects | A unique name and private SQLite storage per object, on one thread. An `await` on a `fetch` lets other requests in, so a read-modify-write across one needs a version check | [Rules of Durable Objects](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/) |
| 3 | SQLite and alarms | `Storage::sql()` is synchronous; a `transaction` wraps the event append and the outbox row; deletes count as writes. An alarm handler must be idempotent, and each `setAlarm()` is a row written | [SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/) |
| 4 | Hibernation | `accept_web_socket` lets an idle object leave memory while clients stay connected. No timers; state goes in attachments | [WebSockets in Durable Objects](https://developers.cloudflare.com/durable-objects/best-practices/websockets/) |

## Patterns and further reading

- Hexagonal architecture: the `Clock`, `EventStore`, `Outbox`, `PaymentGateway`, `Mailbox` and `IdGen` ports. Alistair Cockburn, ["Hexagonal architecture"](https://alistair.cockburn.us/hexagonal-architecture/) (2005).
- Transactional outbox: Chris Richardson, ["Transactional outbox"](https://microservices.io/patterns/data/transactional-outbox.html), *Microservices Patterns* (2018).
- Bulkhead: the storefront Worker apart from the API Worker. Michael Nygard, *Release It*, 2nd ed., ch. 5, "Stability Patterns".
