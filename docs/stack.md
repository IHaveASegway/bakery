# Stack

Every technology the bakery uses or plans to use: its pin, what it owns, why it won, and what came second; also what was rejected, when upgrades happen, and what is new to learn. The choices that shape the rest have their own ADRs, listed under Doors below. Toolchain mechanics are in [delivery.md](delivery.md), prices in [cost.md](cost.md).

Status: Updated in PR 17 · 2026-11-06; reconciled with the code on 2026-11-09, with the [techniques as built](#techniques-as-built)

## Shape

The made-up bakery, Proof of Concept Bakery, is two systems on the site's Cloudflare account and zone. Astro builds the storefront and staff console as static files, and an assets-only Worker, `bakery-web`, serves them, so a public page view runs no code. Everything on a server is Rust: one Worker, `bakery-api`, compiled to `wasm32-unknown-unknown`, which holds every Durable Object (DO) class, the Queue consumer and the cron handler. The domain lives in crates that know nothing about Cloudflare, so `cargo test` runs it natively. State is SQLite-backed DOs, one per aggregate. GitHub Actions builds, gates and deploys. Before the launch pull request (PR 11) nothing was deployed and both Workers ran on `wrangler dev`. Since the launch on 2026-11-06 both serve their custom domains on Workers Paid.

## Upgrade policy

Upgrades arrive as Dependabot PRs and pass the same pipeline as everything else. Versions and dates are as of 2026-11-04. The Dependabot configuration is in [delivery.md](delivery.md).

| What | Rule | Why |
|---|---|---|
| Pins and Dependabot | Every crate and package is pinned exactly; lockfiles are committed; CI passes `--locked`. Dependabot (cargo, npm, github-actions) opens one grouped weekly PR for minors and patches, and a major in its own PR | A build is the same everywhere, an upgrade is a visible diff, and a major gets a migration note |
| `worker`, `worker-build` | Exact pins that move together; read the changelog before every bump, because workers-rs is 0.x and a minor may break | Two breaking releases in a year ([site ADR 0014](https://github.com/IHaveASegway/website/blob/main/docs/adr/0014-typescript-on-workers.md)) |
| `wasm-bindgen` | Follows `worker`, never bumped by hand | The two must agree on the Wasm interface |
| Rust | Track stable within a month of each release | An old toolchain drifts from the crates' minimum versions |
| Stripe API version | Pinned in a header on every call; bumped in its own PR. As built in PR 5 the adapter sends `Stripe-Version` whenever `STRIPE_API_VERSION` is set; since 2026-11-06 it is pinned in `wrangler.jsonc` to `2026-10-28.endive` (as of 2026-11-09) | An unpinned version changes under a running system |
| Astro, Wrangler, Node, pnpm, TypeScript, VROOM, gitleaks | The site's rules, taken from [its upgrade policy](https://github.com/IHaveASegway/website/blob/main/docs/stack.md#upgrade-policy): Astro majors wait for x.1; Wrangler `^4.152.0`; Node on the Active LTS line; pnpm 11.x; TypeScript 6.0.x; VROOM by copying the site's newer build; gitleaks bumped quarterly with its sha256 | Two repositories upgrade the same way |
| `compatibility_date` | Bumped quarterly, alone, per Worker, after reading the flag changes | A stale date is a missing feature, not an outage ([docs](https://developers.cloudflare.com/workers/configuration/compatibility-dates/)) |

## Patterns and further reading

- Hexagonal architecture: the `Clock`, `EventStore`, `Outbox`, `PaymentGateway`, `Mailbox` and `IdGen` ports. As built (2026-11-09) two ports have Worker adapters, `Clock` (`workers/api/src/clock.rs`) and `PaymentGateway` (`workers/api/src/stripe.rs`); `EventStore`, `Outbox`, `Mailbox` and `IdGen` are used by the native tests' fakes, and the objects use `workers/api/src/objects/stream.rs` directly. On 2026-11-09 the session decided, under Joseph's delegation of the same day and revisable, that a port nothing in production implements is removed, unless the app layer's own tested logic needs the seam (roadmap R22, the audit and the change R68). ["Hexagonal architecture"](https://alistair.cockburn.us/hexagonal-architecture/) (essay, 2005).
- Transactional outbox: ["Transactional outbox"](https://microservices.io/patterns/data/transactional-outbox.html) (microservices.io), and *Microservices Patterns* (book, 2018).
- Bulkhead: the storefront Worker apart from the API Worker. *Release It!*, 2nd ed. (book, 2018), ch. 5, "Stability Patterns".
